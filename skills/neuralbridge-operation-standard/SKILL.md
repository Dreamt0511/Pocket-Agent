# NeuralBridge MCP 操作标准规范
## 核心三原则（强制执行）
1. **坐标绝对禁止猜测**：所有点击/长按/滑动的坐标必须 100% 来自 `android_get_ui_tree` 的返回结果，禁止通过截图视觉识别、估算坐标
2. **每步必验证**：任何操作执行后必须通过截图或 UI 树查询验证操作结果，确认成功后再进行下一步
3. **专用工具优先**：优先使用对应场景的专用工具，禁止用通用点击/滑动模拟：
   - 启动应用用 `android_launch_app`，禁止点击桌面图标
   - 系统操作用 `android_global_action`，禁止点击导航栏按钮
   - 查找元素用 `android_find_elements`/`android_get_ui_tree`，禁止视觉识别

## 一、元素定位标准（怎么找坐标）
### 1. 定位流程
```mermaid
graph LR
A[需要操作某个元素] --> B[调用 android_get_ui_tree 获取全量 UI 结构]
B --> C[通过 text/resource_id/desc 匹配目标元素]
C --> D[提取元素 bounds 字段: [left, top, right, bottom]]
D --> E[计算精确中心点: x=(left+right)/2, y=(top+bottom)/2]
E --> F[使用计算得到的坐标执行操作]
```

### 2. bounds 解析规则
- UI 树返回的 bounds 格式为 `[left, top, right, bottom]`，分别代表元素的四个边界坐标
- 中心点计算必须严格按照公式：
  ```python
  x = (left + right) // 2
  y = (top + bottom) // 2
  ```
- 禁止对坐标进行任何"大概"、"差不多"的调整

### 3. 元素匹配优先级
1. 优先用 `resource_id` 匹配（稳定性最高，不会随语言/主题变化）
2. 其次用 `text` 匹配（可见文字，准确性高）
3. 最后用 `content_desc` 匹配（无障碍描述）
4. 禁止用位置顺序匹配（比如"第三个按钮"）

## 二、操作确认标准（怎么确认点对了）
### 1. 点击前确认
执行操作前必须确认：
- 匹配到的元素 `text/resource_id` 和目标完全一致
- 元素的 `bounds` 在屏幕可见范围内（y 坐标在 0~屏幕高度之间）
- 元素具有可交互属性（`flags` 包含 `c`=可点击、`f`=可聚焦等）

### 2. 典型场景确认要点
| 操作类型 | 确认内容 |
|---------|---------|
| 点击按钮 | 确认按钮 text 是目标文字，且 bounds 符合预期 |
| 打开应用 | 确认包名正确，优先用 `android_launch_app` |
| 输入文本 | 确认输入框已获得焦点（光标出现） |
| 长按操作 | 确认长按位置在元素范围内，且时长不会触发系统手势 |

## 三、结果验证标准（怎么确认操作成功）
### 1. 验证方式（二选一即可，优先用 UI 树）
#### 方式1：UI 树验证（最快最准确）
操作后重新调用 `android_get_ui_tree`，确认：
- 目标元素状态变化（比如按钮消失、文本变化、新元素出现）
- 页面 package_name 符合预期（比如启动应用后 package_name 变为目标应用）

#### 方式2：截图验证（直观）
操作后调用 `android_screenshot`，肉眼确认：
- 操作效果符合预期（比如应用打开、页面跳转、菜单弹出）
- 没有出现误操作（比如返回桌面、打开错误应用）

### 2. 验证失败处理
如果验证不通过：
1. 立即停止后续操作
2. 重新获取 UI 树定位元素
3. 分析失败原因（坐标错误、元素消失、系统拦截等）
4. 调整后重试，禁止连续盲目点击

## 四、典型操作完整流程示例
### 示例：打开笔记应用并点击新建按钮
```
1. 【定位】调用 android_get_ui_tree 获取桌面 UI 结构
2. 【匹配】找到 text="笔记" 的应用图标元素，bounds=[931,2116,1111,2296]
3. 【计算】中心点 x=(931+1111)/2=1021, y=(2116+2296)/2=2206
4. 【操作】调用 android_tap(x=1021, y=2206)
5. 【验证】调用 android_get_ui_tree，确认 package_name 变为 com.miui.notes
6. 【定位】在新 UI 树中找到 resource_id="note_add" 的新建按钮，bounds=[931,2116,1111,2296]
7. 【计算】中心点 x=1021, y=2206
8. 【操作】调用 android_tap(x=1021, y=2206)
9. 【验证】调用 android_screenshot，确认进入新建笔记界面
```

## 五、禁止行为（违者直接视为操作失败）
❌ 禁止在没有 UI 树依据的情况下猜测坐标
❌ 禁止通过截图视觉识别坐标后点击
❌ 禁止操作后不验证直接进行下一步
❌ 禁止用点击桌面图标的方式打开应用，必须用 `android_launch_app`
❌ 禁止在自定义 WebView 页面使用 `android_input_text`（先确认输入框是标准 EditText）
❌ 禁止长按超过 500ms，避免触发系统全局手势

## 六、常见问题解决方案
### 1. 元素找不到
- 检查是否在正确的页面
- 尝试滚动页面后重新获取 UI 树
- 用 `android_find_elements` 按条件搜索

### 2. 点击无反应
- 确认元素 `flags` 包含可点击属性
- 确认坐标计算正确
- 尝试点击元素其他位置（比如左上角，不要只点中心点）

### 3. 输入失败
- 确认输入框已获得焦点
- 确认输入框是标准 Android EditText，不是自定义 WebView
- 降级为剪贴板粘贴方案：`set_clipboard` → 长按 → 点击粘贴
- **非标准输入框（如拼多多搜索框、自定义渲染输入框）适配方案**：
  1. 这类输入框无法通过resource_id匹配，也不支持直接识别为EditText元素，无需等待焦点提示，直接点击输入框可见区域中心即可激活
  2. 即使调用`android_input_text`返回"元素找不到"错误，实际部分应用仍会接收输入，可直接点击搜索/提交按钮尝试
  3. 若仍失败，先将目标文本复制到剪贴板，长按输入框区域1000ms，无需找到粘贴按钮，直接点击搜索按钮，主流电商/社交应用会自动识别剪贴板内容执行搜索
  4. 清空原有内容方案：如果长按找不到全选按钮，连续按delete键清空，或直接输入新内容覆盖，无需完全清空即可触发搜索
- **自定义WebView输入框（如DeepSeek等跨端应用通用）适配方案**：
  1. 识别信号：调用 `android_input_text` 返回 `Could not get node reference for element` 错误，且页面无标准EditText元素
  2. 操作流程：
     - 点击输入框可见区域中心激活（优先点击占位文本所在位置）
     - 使用 `android_set_clipboard` 将目标文本存入系统剪贴板
     - 长按输入框区域1000~1500ms，若粘贴菜单未弹出，重试1~2次
     - 若未找到「粘贴」元素，点击长按点上方约 100px 位置触发粘贴
     - 验证内容粘贴成功后点击发送/搜索按钮，若仍失败，先关闭所有系统弹窗（权限申请、通知等）后重试
  3. 禁止操作：直接调用系统`input`命令（Termux环境无执行权限，会触发空指针异常）
