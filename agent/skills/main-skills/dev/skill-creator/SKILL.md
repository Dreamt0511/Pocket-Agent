# Skill Creator (主Agent版)

当你完成一个多步骤任务或解决了一个问题后，判断是否值得将流程沉淀为技能。

## 第一步：判断值不值得沉淀

满足以下条件才沉淀：
- 步骤 >= 3 步
- 任务成功完成（失败的不沉淀）
- 以后可能重复执行（一次性任务不沉淀）
- 流程有参考价值（不是简单到一句话能说清的）

不沉淀的情况：
- 单步操作（直接用工具就行）
- 失败的任务
- 一次性的临时操作
- 已有相同功能的技能存在

## 第二步：读取已有技能格式

**必须先读取技能创建规范**，用 file_read 读取：
`agent/skills/executor-skills/skill-creator/SKILL.md`

对照其中的格式要求编写，确保格式一致。

## 第三步：编写技能

技能写入 `agent/skills/auto-skills/main/<技能名称>/SKILL.md`

### 技能名称
从任务目标提取关键词，最多3个词用下划线连接（如 `deploy_android_app`、`sqlite_fts5_setup`）

### SKILL.md 格式
```markdown
---
name: <技能名称>
description: <一句话描述，100字以内>
---

# <技能名称>

## 任务目标
<这个技能解决什么问题>

## 前置条件
- 需要什么环境/工具/权限

## 执行步骤
1. 步骤1描述
2. 步骤2描述
3. 步骤3描述
...

## 关键操作
- 用到的工具和参数
- 容易出错的地方和解决方案
- 重要的配置项

## 适用场景
什么情况下应该使用这个技能

## 参考
- 相关文件路径
- 相关命令
```

## 第四步：沉淀为程序记忆

如果流程不适合写成独立技能（比如只是一个小技巧），用 save_memory 存为事件记忆即可：
`save_memory(content="学到的技巧: ...", type="episodic", tags=["技巧"])`

## 规则
- 先判断再写，不要什么都沉淀
- 格式必须参考 executor 版 skill-creator 的规范
- 沉淀不阻塞用户：先完成当前任务，再写技能
- 技能名称简洁明了，不用太长
