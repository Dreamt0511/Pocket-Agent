# Pocket-Agent LangChain 重构设计文档

## 项目背景
Pocket-Agent 是一个运行在 Android Termux 环境下的轻量级 AI 代理，目前已实现自定义 Agent 循环、工具调用、技能系统、MCP 服务集成（安卓控制）、长期记忆和终端 UI。本次重构目标是使用 LangChain 官方标准替换现有自定义 Agent 实现，同时保持所有现有功能不变，为后续语义检索、多模态等扩展打下基础。

## 目标环境
- 运行环境：Android Termux (Python 3.13)
- 模型部署：llama.cpp server 独立部署，提供 OpenAI 兼容 API
- 模型：GELab-Zero-4B-preview-q4_k_m.gguf (4B 参数，q4 量化)
- 硬限制：上下文窗口 ≤ 29000 tokens (防止闪退)

### 核心设计要点
1. **LLM 连接**：使用 LangChain 官方 `ChatOpenAI` 直接连接本地 llama-server，零自定义适配代码，原生支持工具调用和流式输出
2. **工具适配**：
   - 现有基础工具和 MCP 工具使用 `@tool` 装饰器自动封装为 LangChain 标准工具
   - Superpowers 技能通过通用工具适配器封装，保持 `superpowers <command>` 调用方式不变
3. **记忆系统**：
   - 对话历史：自定义 `PocketCheckpointer` 持久化到本地 JSON 文件，重启不丢失
   - 长期记忆：保留现有 `LongTermMemory` 实现，预留语义检索扩展接口
4. **上下文保护**：三层保护机制防止超过 30000 tokens 硬限制
   - 服务端：llama-server 启动参数设置 `-c 29000`
   - Agent 层：`MessagesTrimMiddleware` 自动截断到 28000 tokens
   - 工具层：工具返回结果超过 4000 字符自动截断
5. **中间件**：通过 `wrap_tool_call` 实现现有反死循环、MCP 健康检测等逻辑，不需要修改核心代码

## 迁移实施步骤
### 阶段 1：基础适配层开发
1. 新增 LangChain 依赖到 requirements.txt
2. 实现 `PocketCheckpointer` 持久化记忆类
3. 工具适配：封装现有所有工具为 LangChain 标准 `@tool`
4. 实现 Superpowers 技能通用适配器

### 阶段 2：Agent 核心集成
1. 基于 `create_agent()` 实现新的 Agent 核心
2. 实现并注册中间件（上下文截断、反死循环、MCP 健康检测）
3. 适配现有 UI 流式输出到 LangChain 回调系统

### 阶段 3：主流程集成
1. 替换 `main.py` 中的 `PocketAgent` 实例为 LangChain Agent
2. 适配现有命令处理逻辑（help/undo/superpowers 等）
3. 适配撤回消息功能到新的记忆系统

### 阶段 4：测试与优化
1. 全功能测试，确保所有现有功能正常工作
2. 性能优化，控制内存占用在 100MB 以内
3. 稳定性测试，验证上下文保护机制有效

### 阶段 5：扩展预留
1. 新增语义搜索工具框架（预留接口，不实现具体逻辑）
2. 新增多模态图片分析工具框架（预留接口，不实现具体逻辑）
3. 完善文档，说明后续扩展方法

## 非功能性要求
1. **性能**：推理速度 ≥ 15 tokens/秒（骁龙8 Gen2 设备）
2. **内存**：Python 进程内存占用 ≤ 150MB
3. **稳定性**：连续运行 24 小时无崩溃，上下文溢出自动恢复
4. **兼容性**：所有现有用户交互方式完全不变，无感知迁移

## 后续扩展路线图
1. **v1.1**：语义记忆检索，基于本地嵌入模型
2. **v1.2**：多模态支持，图片分析能力
3. **v1.3**：技能商店，支持在线下载安装新技能
4. **v1.4**：多 Agent 协作，支持同时运行多个 specialized Agent

## 风险控制
- **回滚方案**：保留原有自定义 Agent 实现，重构后作为备选方案，出现问题可一键切换
- **兼容性保障**：所有外部接口（命令格式、工具调用方式、配置文件）完全不变
- **渐进式迁移**：分阶段合并代码，每阶段都可独立运行验证
